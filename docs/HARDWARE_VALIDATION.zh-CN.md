# CMC301 食谱动作实测（2026-09-24）

设备：xiaomi.cooker.cmc301，固件 1.1.3。调用实际集成的 facade、后端与食谱编码器；Windows 测试脚本只替代 HA 的 Platform 枚举，并在传输层增加命令白名单和一次性启动保护。短测另设独立停止保护；后续用户明确授权的完整快煮不设自动停止。Token 未写入报告或仓库。

下表短测的用户授权为单次加热不超过 120 秒。以下时间从测试启用计时到确认停止，包含预约等待和通信时间，**不是实际通电加热时长**。主脚本按计划停止，独立进程在 100 秒期限到达时也会发停止；本次未触发独立进程兜底。

| 测试 | 参数 | 计时窗口 | 结果 |
|---|---|---:|---|
| 精煮预约 | 60分钟、偏硬、不自动保温、180分钟后完成 | 4.424秒 | action 2.6 成功；首次状态读取超时后提前停止；停止后读回菜单2、60分钟、口感2 |

## 已确认

- 本地 action 2.6 接受带校验的完整食谱；立即启动和预约路径均得到实机状态反馈。
- 精煮口感参数2可在设备属性中读回；无需依赖此前无效果的单属性口感写入。
- 煮粥目标时长可由默认90改为60；设备反馈不是此前默认启动路径的滞留参数。
- 预约填写的是距完成的分钟数：61分钟对应约3660秒剩余时间。
- action 2.2 能停止上述执行并回到待机。存在偶发丢包，停止和查询必须保留有限重试；启动不能因应答丢失自动重发。
- 上表短测最后均确认待机；当时最终故障0、远程许可true。面板设置保持原来的 `00050101`。当时保留的是煮粥、60分钟、口感0的菜单参数，没有为恢复旧选择而额外启动。

## 不能从本次测试推断的内容

- 状态3在预约倒计时进入60分钟以内后仍未变成2。现场只确认从开始显示“1:01后完成”，未能判断加热起点，也没看到独立预约指示。因此把它显示为“预约烹饪中”，不推导加热器是否通电。
- 自动保温没有独立读回属性；后续完整快煮已由用户确认自动进入保温，见末节。关闭自动保温后的完整结束行为仍未验证。
- 没有逐一启动全部13个食谱，也未验证每条程序的完整加热曲线。菜单模板已做离线校验，不等于全部实机烹饪验收。
- 面板自选保存 action 2.5 已在后续完成非加热测试及现场显示核对，见下节。
- 未测试云端完成通知是否实际送达手机。

## 温度历史与代码修正

重测记录到历史由空串增长为 `1a1a1a`、`1a1a1a1a`、`1a1a1a1a1a`。按官方插件的算法，跳过前两个字节、排除 AA 后可解析末样本26°C；这不是独立温度计校准，也不足以证明前两字节在此固件中的物理含义。仅 `1a` 仍按数据不足处理。停止后的实际历史被清空。

0.3.0b0 在预约初始缓存空历史两分钟，导致测试期间已经出现的新样本仍不显示。0.3.0b1 改为：运行/预约/保温中历史为空时最多30秒重读一次；取得样本后恢复120秒间隔；工作状态或食谱变化时立即重新读取，停止后不继续显示已失效缓存。

相关采样已去除设备和网络标识，纳入 `tests/fixtures/cmc301_hardware_session.json`。新增离线重放测试覆盖预约、立即启动、时长/口感反馈、迟到的温度样本以及停止后清空。修正后测试通过，不需要再次加热。

## 后续：面板自选保存（无加热）

用户明确要求通过面板核对自选保存。使用实际集成 `set_panel_recipe`，将煮粥时长设为130分钟，写入自选槽 index=4，发送 action 2.5（带 `info_` 前缀）。设备返回成功，并读回：

- 工作状态1（待机），故障0，剩余时间0。
- 模式5（自选），食谱ID3（煮粥），目标时长130分钟。
- 面板设置仍为原值，未发送任何启动指令。

用户现场确认：面板自动切换到自选、闪烁待开始，时长准确显示 `2:10`。设备应答、属性读回和现场显示三项一致，面板自选保存实测通过。该保存操作保留煮粥130分钟，没有启动加热。

## 后续：完整快煮与自动保温

用户明确授权完成代码后启动一次快煮，开启自动保温并让设备自然完成，用于烧水去异味。本次授权取代此前针对短测的两分钟限制；未设置自动停止，也未重复发送启动。

实际集成发送超快饭（食谱ID1）、28分钟、立即启动、自动保温开启的完整食谱，action 2.6 返回 code 0。启动后读回状态2、模式1、食谱ID1、目标28分钟、剩余1678秒、故障0。

随后用户现场确认“自动保温了”。因此，超快饭完整执行后自动进入保温的路径已获得现场验证；不是通过独立自动保温属性读回或 HA 界面观察得出的结论。关闭自动保温后的结束行为、其余菜单完整周期和 HA 实际部署验收仍待日常使用核对。本次确认后没有追加设备控制命令。
