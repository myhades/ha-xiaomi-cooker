# normal3 无加热实测与新增控制

2026-09-25，设备 `chunmi.cooker.normal3`，原始版本字段 `0003000c`。依据用户提供的插件 1002206 v6，模块 10448、10445、10451、10991、11024。未发送 `set_start`、预约启动、恢复出厂或删除食谱；测试前后及各步骤读回均为 `waiting`。

之前未暴露这些实体属于集成覆盖不足，不能据此判定设备不支持。

| 功能 | 调用与结果 | 集成处理 |
|---|---|---|
| 自动熄屏 | `set_interaction` 的开关位可写可读 | 与 CMC301 共用选择器 |
| 熄屏时长 | 2、3、4 均读回5；5–10逐项准确读回 | 仅提供 Off、5–10分钟 |
| 开盖超时报警 | 开关后状态字节 `14`→`04`，恢复后 `14` | 可写开关，替代旧只读传感器 |
| 开盖保温超时 | 4→6分钟，读回 `050615`，再恢复 `050415` | 选择器，使用插件的2/4/6/8/10分钟选项 |
| 完成推送 | `set_setting ["00","00",""]`，首字节读回00；恢复01 | 可写开关；没有通过实际烹饪验证手机推送送达 |
| 自选食谱 | `set_menu`，食谱头第2字节设置0x80并重算CRC；炖汤1615读回`favorite=064f` | 可写“自选食谱”选择器，独立读回favorite |
| 停止 | 待机发送现有 `set_func ["end02"]` 返回ok，仍待机 | 不改变现有停止协议；没有据此声称验证运行中停止 |
| 温度、状态 | `get_prop ["all"]` 正常返回，26–28°C、待机 | 实际后端读取通过 |
| 温度历史 | `get_temp_history` 返回`0` | 待机时没有历史样本，不构造曲线 |
| 交互设置专用读取 | 插件的 `get_interaction` 调用无响应 | 使用实际可用的 `get_prop ["all"]` 设置和超时字段 |

所有设置写入只发送一次，并核对设备读回。`set_interaction` 必须按本插件使用一个逗号分隔字符串，例如 `["4,5,4,15"]`；不能直接使用依赖库另一种四参数格式。写入时保留其余交互位、各菜单保温位及独立报警延时。

自选槽遵循插件 `canFavorite` 限制，只提供菜单ID大于4的扩展食谱。精煮、快煮、煮粥、保温仍从烹饪菜单选择，不能错误写入自选槽。保存会改变面板选中菜单和对应准备参数，但不会开始加热。

实测后恢复原面板精煮菜单、60分钟、原自选热饭、30分钟、自定义准备参数、保温位、交互设置和推送开关。自选食谱的完整旧程序无法从设备导出；恢复使用相同菜单的内置官方模板，读回菜单及参数匹配，不声称旧程序逐字节一致。`get_setting` 的附带第二字节由00变为01，首字节的推送设置已恢复；未把该附带标志当作用户开关或强行复位。

未照搬 CMC301 的全局蜂鸣、全部模式灯、远程许可和沸腾反馈：本型号活动插件路径及实测没有提供等价可用接口。`set_taste`、`set_delete` 等共用方法的存在不足以证明当前页面或本固件需要它们；口感使用已有食谱头，删除和恢复出厂不属于本轮非破坏测试。预约使用当地钟表时间，未进行可能开始加热的硬件验收。
